# Визуальные правила «Керамики»

Источник: учебная палитра v1. [«Керамика», фрейм «00 · Компоненты и токены»](https://www.figma.com/design/LfGN425jPYlojWrNXMsVWt?node-id=4-210). Этот файл — готовый эталон преподавателя. Студент пишет свой DESIGN.md до создания второго экрана.

| Токен | Значение | Стиль / роль в макете |
|---|---|---|
| background / foreground | #faf7f2 / #292522 | Фон страницы / основной текст |
| card / card-foreground | #ffffff / #292522 | Карточка / текст |
| primary / primary-foreground | #8f3d2e / #ffffff | Акцент / текст на акценте |
| muted / muted-foreground | #f1e8df / #65584f | Приглушённая поверхность / подпись |
| border | #d5c6b8 | Граница поверхности, не индикатор фокуса |
| control | #65584f | Контрастная граница вторичного действия |
| text-title | 2rem / 1.2 | Заголовок страницы |
| text-card-title | 1.25rem / 1.4 | Заголовок карточки |
| text-body | 1rem / 1.5 | Основной текст |
| text-caption | 0.875rem / 1.4 | Подпись |
| radius-card / radius-control | 0.75rem / 0.5rem | Карточка / действие |
| spacing | 0.25rem | Шкала 4/8/16/24 px при корневых 16 px |

Шрифт Manrope локальный, веса 400/600/700. Теней нет. Макеты — визуальная опора; браузерные карточки растут по тексту. Основной контейнер ограничен max-w-7xl, на широком экране появляется дополнительное поле. Это осознанное отличие от растянутого Figma-кадра. border не обязан давать контраст контрола: действие имеет собственную границу control и видимый фокус.

## Компоненты

WorkshopCard общий: название/время; на расписании число мест, на записях statusLabel. Текст статуса не заменять одним цветом. Вызов существующего Button, для перехода Button asChild + Link. Кнопка выполняет действие, ссылка меняет адрес. Высота доступной области от 44 px. Фокус виден.

## Запреты

1. Не добавлять цвета и размеры текста вне таблицы без изменения правил и объяснения.
2. Не копировать WorkshopCard ради нового текста или оттенка.
3. Не убирать следующий шаг у пустоты и ошибки; не заменять button/a кликабельным div.
4. Не добавлять вход, оплату, backend, пакеты и реальные пользовательские данные в эту практику.
5. Не исправлять стиль вторичного экрана вручную в обход принятого цикла: уточнить правило/токен и задачу агенту, проверить результат.

## Проверка

Открыть все 8 адресов README. У error повтор ведёт в success того же экрана. Empty записей ведёт к расписанию. Все состояния на 375; расписание и на 768/1440, записи success на 768/1440. Длинный текст переносится, горизонтальной прокрутки нет. Проверка Tab/Space/Enter обязательна. Скриншоты: docs/screens/.
